# プログラム基本設計書：ピタブロ

## 1. システム要件・技術スタック

* **プラットフォーム:** iOS / Android
* **ゲームエンジン:** Unity (2D Core)
* **プログラミング言語:** C#
* **画面解像度:** 縦画面固定（Aspect Ratio 9:16 を基準にスケーリング対応）
* **データ保存:** ローカル保存（`JsonUtility` を用いたJSONシリアライズ）

## 2. アプリケーション・アーキテクチャ

本プロジェクトは、UIコンポーネントとゲームロジックを分離するため、イベント駆動型（`System.Action` を活用したオブザーバーパターン）をベースに構築する。

### 2.1 主要マネージャー（Singleton / 1シーン1インスタンス）

* **GameManager:** ゲーム全体の進行状態（初期化、プレイ中、リザルト）を管理する。
* **GridManager:** 盤面（8×12の配列）のデータ保持、配置判定、ライン消去のロジックを担当する。
* **InputManager:** スマホのタッチ操作・ドラッグ操作を検知し、BlockControllerへ伝達する。
* **SaveDataManager:** プレイ記録、図鑑の解放状況、シールの獲得状況をJSONファイルとして読み書きする。
* **UIManager:** 画面上のスコア、ボタン操作、ポップアップ演出の表示を統括する。

## 3. コアロジック設計

### 3.1 盤面（グリッド）のデータ構造

* **内部データ:** `int[8, 12]` の2次元配列で管理する。
  * `0`: 空きマス
  * `1以上`: ブロックが配置されている（色やブロックIDを保持）
* **座標変換:** Unityのワールド座標（Transform）と、配列のインデックス（x, y）を相互に変換するメソッドを `GridManager` 内に実装する。

### 3.2 ブロック（テトリミノ）の設計

* **BlockData (ScriptableObject):**
  * 各ブロックの「形状（4つのマスの相対座標リスト）」「色（Sprite）」をマスタデータとして定義する。
* **BlockController (MonoBehaviour):**
  * 各ブロックのプレハブ（Prefab）にアタッチする制御スクリプト。
  * **ドラッグ処理:** タッチ座標に追従（`Transform.position` の更新）。
  * **スナップ処理:** 指を離した際、現在の座標を `Mathf.RoundToInt()` で四捨五入し、最も近いグリッド座標を算出。`GridManager` に配置可能か（障害物や壁がないか）を問い合わせ、可能なら吸着させる。
  * **回転処理:** タッチ（タップ）検知時、各子要素（4つのマス）のローカル座標を90度回転させる行列計算を行う。

### 3.3 ライン消去処理フロー

1. ブロック配置確定時、`GridManager` がY軸（0〜11）を下からスキャンする。
2. 横1列（X軸0〜7）の値がすべて `0` 以外であれば、その列を「消去対象」としてリストアップ。
3. 消去演出（パーティクル再生）を呼び出す。
4. 対象列のデータを `0` にクリアし、それより上の列のデータを1段（対象が複数ならその分）下にシフトする。
5. 実際の画面上のSprite（ブロック画像）のTransform座標も配列に合わせて下に移動させる。

## 4. シーン（画面）遷移設計

Unityのシーンロードのオーバーヘッドを減らすため、基本は「1シーン（MainScene）」で構成し、UIのCanvasの表示・非表示で画面を切り替える設計とする。

1. **TitleUI:** スタートボタン、保護者向けボタン（長押し判定）。
2. **ModeSelectUI:** はじめてモード、ブロック道、おてほんモードの選択。
3. **InGameUI:** ゲーム画面（盤面、チェンジボタン、Undoボタン）。
4. **CollectionUI:** どうぶつ図鑑、シール帳の表示。
5. **ReportUI:** 成長レポート（プレイ時間やクリア数のデータバインディング表示）。

## 5. データ保存（セーブデータ）構造

`PlayerData` クラスを定義し、JSON形式で保存する。

```csharp
[System.Serializable]
public class PlayerData
{
    public int totalPlayTimeMinutes; // 総プレイ時間
    public int clearedStageCount;    // クリアした課題数
    public List<int> unlockedAnimals; // 解放済み動物のIDリスト
    public List<int> unlockedSeals;   // 獲得済みシールのIDリスト
    public string lastPlayDate;      // 最終プレイ日（連続プレイ判定用）
}

## 6. お助け機能の実装方針

* **Undo（1手戻す）:**  
  GridManager にスタック（Stack<int[,]> または操作履歴のコマンドオブジェクト）を持たせ、ブロック配置前の盤面状態と、配置したブロックのインスタンスを記録しておく。ボタン押下で状態をPopし盤面を復元する。

* **チェンジボタン:**  
  手持ちのブロックオブジェクトを破棄（Destroy）し、ランダムな BlockData を元に新たなプレハブを生成（Instantiate）して初期位置に配置する。
